1. Alur Utama End-to-End (Panitia → Anggota → Presensi → Rekap)

flowchart TD
    A([Mulai]) --> B[Panitia login
UC-01 FR-01]

    C --> D[Ajukan proposal digital
UC-03 FR-03]
    D --> E{Pembina review}
    E -- Revisi --> C
    E -- Ditolak --> Z([Acara dibatalkan])
    E -- Disetujui --> F[Publikasikan acara
FR-02]
    F --> G[Notifikasi acara baru
UC-08 FR-10]
    G --> H[Anggota login & buka Daftar Acara]
    H --> I[RSVP / daftar acara
UC-04 FR-04]
    I --> J{Kuota tersedia?}
    J -- Tidak --> K[Tolak / Waiting List]
    J -- Ya --> L[Generate QR unik
per peserta per acara]
    L --> M[Kirim QR + notifikasi konfirmasi]
    M --> N[Acara berlangsung:
Panitia buka Scan Presensi]
    N --> O[Anggota tunjukkan QR]
    O --> P[Scan QR → verifikasi
UC-05 FR-05]
    P --> Q{QR valid?}

FR-06]
    R --> S

UC-06 FR-07]
    V --> W[Dasbor partisipasi + ekspor
PDF/Excel/CSV FR-08, FR-12]

2. UC-04 — Pendaftaran / RSVP Acara (FR-04)

flowchart TD
    A([Anggota buka Daftar Acara]) --> B[Sistem tampilkan acara
+ sisa kuota]
    B --> C[Anggota pilih acara → Daftar]
    C --> D{Sudah terdaftar?}
    D -- Ya --> E[Tampilkan QR yang sudah ada
cegah duplikasi A2]
    E --> H
    D -- Tidak --> F{Kuota penuh?}
    F -- Ya --> G[Tawarkan Waiting List
atau pesan kuota penuh A1]
    G --> H
    F -- Tidak --> I[Catat sebagai peserta]
    I --> J[Generate kode/QR unik]
    J --> K[Kirim notifikasi konfirmasi + QR]
    K --> H([Anggota menerima QR presensi])
    classDef dec fill:#78350f,stroke:#fbbf24,color:#fff;
    class F,D dec;

3. UC-05 — Presensi via QR Code + Mode Cadangan (FR-05, FR-06)

flowchart TD
    A([Panitia buka Scan Presensi]) --> B[Autentikasi panitia pada perangkat
include UC-01]
    B --> C[Anggota tunjukkan QR]
    C --> D[Panitia pindai QR via kamera]
    D --> E{QR terbaca?}
    E -- Tidak --> F[Input kode manual 6 digit
FR-06 mode cadangan]
    F --> G
    E -- Ya --> G[Verifikasi keabsahan kode
vs acara aktif]
    G --> H{Kode valid & belum dipakai?}
    H -- Tidak --> I[Tolak pencatatan ganda
+ peringatan A2]
    I --> C
    H -- Ya --> J[Catat status Hadir
+ stempel waktu]
    J --> K[Konfirmasi visual nama anggota]
    K --> L{Lanjut peserta lain?}
    L -- Ya --> C
    L -- Tidak --> M([Selesai sesi presensi])
    classDef dec fill:#78350f,stroke:#fbbf24,color:#fff;
    classDef fail fill:#881337,stroke:#fb7185,color:#fff;
    class E,H,L dec;
    class I fail;

4. UC-03 — Pengajuan & Validasi Proposal Acara (FR-03)

flowchart TD
    A([Panitia siapkan proposal]) --> B[Unggah proposal digital]
    B --> C[Status: Diajukan
+ timestamp]
    C --> D[Notifikasi ke Pembina]
    D --> E{Pembina meninjau}
    E -- Setuju --> F[Status: Disetujui
acara boleh dipublikasikan]
    E -- Revisi --> G[Status: Revisi + catatan]
    G --> B
    E -- Tolak --> H[Status: Ditolak + alasan]
    H --> I([Acara tidak dipublikasikan])
    F --> J([Acara siap tayang ke anggota])
    classDef dec fill:#78350f,stroke:#fbbf24,color:#fff;
    classDef fail fill:#881337,stroke:#fb7185,color:#fff;
    class E dec; class H,I fail;

5. UC-06 — Rekap & Unduh Laporan Kehadiran (FR-07, FR-08, FR-11, FR-12)

flowchart TD
    A([Pengurus/Pembina buka Laporan Kehadiran]) --> B[Pilih filter
per acara / rentang tanggal / per anggota]
    B --> C[Klik Unduh Laporan]
    C --> D{Ada data?}
    D -- Tidak --> E[Pesan 'Data tidak ditemukan'
tanpa berkas kosong A1]
    E --> B
    D -- Ya --> F[Hitung ringkasan
hadir / tidak hadir / %]
    F --> G[Generate berkas
PDF / Excel / CSV]
    G --> H[Taut unduh tersedia]
    H --> I([Laporan siap dilaporkan
ke kemahasiswaan/SKPI])
    classDef dec fill:#78350f,stroke:#fbbf24,color:#fff;
    class D dec;

6. Diagram State — Status Acara & Status Presensi

stateDiagram-v2
    [*] --> Draft
    Draft --> Diajukan: ajukan proposal
    Diajukan --> Disetujui: pembina setuju
    Diajukan --> Revisi: minta revisi
    Revisi --> Diajukan: perbaiki & kirim ulang
    Diajukan --> Ditolak: pembina tolak
    Disetujui --> Dipublikasikan: tayang ke anggota
    Dipublikasikan --> Berlangsung: jendela presensi dibuka
    Berlangsung --> Ditutup: akhiri presensi
    Dipublikasikan --> Dibatalkan: ada peserta → batal + alasan
    Berlangsung --> Dibatalkan: batal darurat + alasan
    Ditutup --> [*]
    Ditolak --> [*]
    Dibatalkan --> [*]
    
stateDiagram-v2
    [*] --> Terdaftar: RSVP sukses + QR dibuat
    Terdaftar --> Hadir: QR valid dipindai
    Terdaftar --> HadirCadangan: kode manual 6 digit valid
    Terdaftar --> TidakHadir: acara ditutup tanpa presensi
    Hadir --> [*]: immutable (stempel waktu)
    HadirCadangan --> [*]: ditandai 'mode cadangan'
    TidakHadir --> [*]
